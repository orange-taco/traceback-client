# Traceback Wireframe

## 목적

- 브랜드명: `TRACEBACK`
- 현재 단계: 웹사이트 디자인 와이어프레임 설계
- 프론트엔드 저장소: `traceback-client`
- 프론트엔드 기준: Remix + Tailwind
- 우선순위: 브랜드 표면 확정 -> 구매 흐름 명확화 -> 기능 범위 확정

이 문서는 일반 커머스 와이어프레임이 아니라 `관찰 기반 시각 아카이브처럼 보이는 커머스`를 정의한다.

## 디자인 원칙

### 핵심 방향

- 첫 화면은 세일 배너가 아니라 기록된 장면 1개가 중심이다.
- 상품은 의류 카드보다 기록 항목처럼 보인다.
- 감성 문구보다 좌표, 시간, 노선, 엔트리 번호 같은 정보형 텍스트를 사용한다.
- 구매 버튼, 옵션 선택, 결제 흐름은 실험하지 않는다.
- 화면은 건조하고 정적이어야 한다.

### 피해야 할 것

- 네온, RGB 글리치, 사이버펑크 무드
- 과한 모션과 3D 효과
- 일반 쇼핑몰식 `BEST`, `SALE`, `HOT` 강조
- 설명적인 카피: `urban loneliness`, `disconnected city` 같은 문장

### 시각 언어

- 배경: `off-white`, `dust gray`, `black`
- 강조색: 한 가지 제한적 사용. 권장: `signal red` 또는 `archive blue`
- 타이포그래피: 산세리프 본문 + 모노스페이스 메타 정보
- 이미지 처리: 큰 히어로 이미지 1개, 작은 박스형 크롭, 망점/저해상도 느낌
- 레이아웃: 넓은 여백, 얇은 선, 좌표축 같은 구획

## 정보 구조

### 고객 메뉴

- `Store`
- `Archive`
- `About`
- `Order Tracking`
- `Cart`

초기에는 카테고리를 전면에 두지 않는다. 첫 드롭이 티셔츠 중심이므로 `Store` 내부 필터만 최소 제공한다.

### 주요 사용자 흐름

```text
Instagram
  -> Home
  -> Store
  -> Product Detail
  -> Cart
  -> Checkout
  -> Order Complete
  -> Order Tracking
```

상품 상세 링크로 바로 유입되는 흐름도 동일하게 지원한다.

```text
Instagram
  -> Product Detail
  -> Checkout
  -> Order Complete
```

### 공통 컴포넌트

- `SiteHeader`: 로고, 최소 메뉴, 카트 수량
- `SiteFooter`: 운영 정보, 연락처, 배송/교환 링크
- `RecordMeta`: 좌표, 시간, 노선, 엔트리 번호 표시
- `ImageFrame`: 이미지 주변 얇은 선, 파일명/타임스탬프 캡션
- `ProductRecordCard`: 상품 카드와 기록 카드의 중간 형태
- `PrimaryButton`: 구매/결제용 명확한 버튼
- `OptionSelector`: 사이즈/색상 선택

- 브랜드 첫인상을 기록 아카이브로 고정한다.
- 첫 드롭 상품으로 자연스럽게 이동시킨다.
- 상업적 배너 대신 `기록된 장면`을 보여준다.

### 콘텐츠 규칙

- 히어로 카피는 한 문장 설명이 아니라 메타 정보 묶음으로 구성한다.
- CTA 문구는 `VIEW DROP 001`, `VIEW PRODUCT`, `ENTER STORE`처럼 건조하게 쓴다.
- 히어로 이미지는 첫 드롭 이미지 중 하나를 크게 사용한다.

## About

목표:
- 브랜드를 설명하되 감성 문장으로 흐르지 않는다.
- 컨셉 문서의 핵심만 짧게 노출한다.

### 와이어프레임

```text
+--------------------------------------------------------------------------------+
| About                                                                          |
+--------------------------------------------------------------------------------+
| TRACEBACK records partial images from public spaces.                            |
| The object is not the scene itself, but the remaining trace after recognition.   |
+--------------------------------------------------------------------------------+
| KEYWORDS                                                                       |
| OBSERVATION / RECORD / TRACE / PUBLIC SPACE / RESIDUAL IMAGE / ANONYMITY        |
+--------------------------------------------------------------------------------+
| DO NOT OVER-EXPLAIN THE IMAGE.                                                  |
+--------------------------------------------------------------------------------+
```

웹사이트에 노출되는 문장은 더 줄일 수 있다. 위 문구는 임시이며 최종 카피는 별도 확정한다.

## Tailwind 구현 메모

### 권장 토큰

```ts
const colors = {
  paper: "#f3f0e8",
  ink: "#111111",
  muted: "#77736b",
  line: "#c9c2b6",
  signal: "#b3261e",
  archive: "#1f3f5b",
};
```

### 레이아웃 기준

- `max-w-[1440px] mx-auto`
- 모바일 기본, `md:`부터 2컬럼 전환
- 선 기반 구획: `border-t border-ink/20`
- 메타 텍스트: `font-mono text-[11px] uppercase tracking-[0.18em]`
- 본문: `text-sm md:text-base leading-relaxed`
- 버튼: 검정 배경/흰 글자 1차, 외곽선 2차

### 이미지 컴포넌트 기준

```text
ImageFrame
  wrapper: border border-ink bg-paper
  image: object-cover grayscale optional
  caption: file name / timestamp / entry number
```

첫 구현에서는 CSS 필터를 과하게 쓰지 않는다. 실제 그래픽의 망점과 저해상도 성질을 우선 사용한다.
